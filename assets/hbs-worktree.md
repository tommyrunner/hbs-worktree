# hbs-worktree 工作树协议

本 skill 规定：当会话负责一个需求时，它只在该需求对应的 git worktree 里写代码，
绝不碰主业务代码和其它需求的工作树。

## 什么时候用

- 会话是由面板新建的（第一条消息就是让你读这个 skill）。
- 用户说「绑定 A-a」「我在 A-a 上做」「在 A-a 里改」。
- 会话开始时用户提到某个工作树分支名，或问「我现在绑的是哪个工作树」。
- 你不确定该改哪个目录。

## 硬规矩

1. **先确认绑定，再动手。** 任何写入之前先跑一次 `hbs-wt env`（命令怎么调见下一节）。
   没有绑定时只能回答、不能改代码；但第一条消息里如果已经写明工作目录，那就是绑定上下文，
   照它执行即可。
2. **只用绝对路径。** 绑定返回的 `root` 是唯一可写目录：`<root>/…`。会话的当前目录仍是主业务代码，
   相对路径会写进主代码。
3. **git 命令一律 `git -C <root> …`。** 禁止在主业务目录里 commit / checkout / merge / push / reset。
4. **不碰主业务分支。** 不切分支、不合并、不删除；合并由用户在面板上点「合并」。
5. **不删工作树。** 删除是用户在面板上的操作，你没有这个权限。
6. **冲突不猜。** 遇到冲突原样上报文件清单，不自动 resolve、不 `--force`。

## 命令

```
hbs-wt env                 本会话绑到哪个工作树（root / branch / base）
hbs-wt list                列出全部工作树
hbs-wt bind A-a            把当前会话绑到 A-a
hbs-wt unbind A-a          解除绑定
hbs-wt repo                当前项目状态（是否 git、主业务分支、当前分支）
```

### 命令怎么调

`hbs-wt` 可能不在 PATH 上——装插件时它只落在 profile 的 node_modules 里，用户不一定执行过 `npm link`。
按这个顺序尝试，**不要**因为第一条失败就停下来问用户：

```bash
# 1) 先试 PATH 上的
hbs-wt env 2>/dev/null && exit 0

# 2) 没有就用插件安装位置（DSH_PROFILE_DIR 在会话环境里一定存在）
node "$DSH_PROFILE_DIR/node_modules/hbs-worktree/bin/hbs-wt.js" env
```

把第 2 条当作等价命令使用即可；只有两条都失败时，才告诉用户「没找到 hbs-wt，
可以在插件目录执行 `npm link`，或者直接在面板上看工作树路径」。

## 标准流程

会话通常由用户在面板上新建：面板会建好工作树、建好这个会话、把它绑到工作树，
并自动发出「读取 skill」的第一条消息。所以第一步永远是确认绑定。

**第一步：确认绑定。**

```
hbs-wt env --session $DSH_SESSION_ID
```

有输出说明已绑定，形如：

```json
{ "root": "/项目/.worktree/A-a", "branch": "A-a", "base": "A",
  "repo": "/项目", "session": "session-…", "note": "解析器重写" }
```

`root` 就是本会话的工作目录。

**第二步：干活。** 所有编辑用 `root` 开头的绝对路径，所有 git 命令 `git -C <root>`。
提交信息用中文，一个逻辑改动一次提交。有远端时收尾 `git -C <root> push`。

**第三步：回报。** 告诉用户：改了哪些文件、提交了几次、是否已推送、还有什么没做完。
**不要自己合并、不要自己切分支**——合并由用户在面板选源/目标执行。

如果第一条指令没有自动发出（面板会提示你手动发送），把它原样发给我：
它会要求我读取本 skill 并给出工作目录，读过之后再动手。

## 没有绑定时的处理

`hbs-wt env` 返回 `null` 时：

- 用户说了分支名 → 先 `hbs-wt bind <分支>` 再干活。
- 用户没说 → 问一句「这个需求放在哪个工作树？可以 `hbs-wt list` 看现有的」。
  不要自建工作树（建工作树是面板的动作），也不要在主业务代码里改。

## 异常对照

| 现象 | 处理 |
| --- | --- |
| `not-a-repo` | 当前项目不是 git 仓库，让用户先在项目里初始化 |
| `unknown-worktree` | 分支名不对，先 `hbs-wt list` 拿准确名字 |
| `no-sessions` | 没有会话上下文，让用户给出 session id 或改在会话里执行 |
| `conflict` | 上报 `details.files`，等用户手动解决 |
| `main-dirty` | 主业务代码有未提交改动，让用户自己处理 |

## 一句话原则

会话只拥有 `root` 这一个目录；主业务代码、分支的生死、合并时机，都是用户和面板的事。
